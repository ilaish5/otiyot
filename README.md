# אותיות נפגשות

אפליקציית ווב לאייפד שמלמדת ילד בן 5 לקרוא מילים מנוקדות: עובר עם העט על המילה המקווקוות, קורא אותה בקול (זיהוי דיבור בעברית), ואחרי כל 5 מילים נכונות מקבל דף צביעה. בלי build — HTML/CSS/JS סטטי. הנתונים נשמרים קודם באייפד ומסתנכרנים ל-Supabase ברקע (ראו "ענן והתחברות").

האפיון המלא: `SPEC.md`.

## הרצה מקומית

```bash
cd "/Users/ilaish/Desktop/פרויקטים/תחומים/אישי/reading=learning"
python3 -m http.server 8765
```

- האפליקציה: http://localhost:8765
- מצב בדיקות: http://localhost:8765/?debug — פאנל קטן בפינה: הקלדת "מה נשמע" במקום מיקרופון, דילוג על המעבר עם העט, סימולציה של שקט, ושורת מצב (מילה · מצב · ניסיונות).

ב-Chrome במחשב זיהוי הדיבור עובד (מול שרת של Google). אזור ההורה נפתח בלחיצה ארוכה (1.5 שניות) על גלגל השיניים.

בפעם הראשונה בכל דפדפן מופיע מסך כניסה: מקלידים את קוד המשפחה (ראו למטה).

## בדיקה על האייפד

המיקרופון עובד רק ב-HTTPS, לכן בודקים על האייפד דרך GitHub Pages (localhost ברשת הביתית לא יספיק).

פריסה ל-GitHub Pages (פעם אחת). הריפו צריך להיות ציבורי כדי ש-Pages יעבוד בחשבון חינמי:

```bash
cd "/Users/ilaish/Desktop/פרויקטים/תחומים/אישי/reading=learning"
git init -b main
git add .
git commit -m "אותיות נפגשות — גרסה ראשונה"
gh repo create otiyot --public --source=. --remote=origin --push
gh api -X POST "repos/{owner}/otiyot/pages" -f "source[branch]=main" -f "source[path]=/"
gh api "repos/{owner}/otiyot/pages" --jq .html_url   # הכתובת, בערך https://<user>.github.io/otiyot/
```

עדכון אחרי שינוי: `git add . && git commit -m "..." && git push` — Pages מתעדכן תוך דקה-שתיים.

על האייפד: לפתוח את הכתובת ב-Safari → שיתוף → "הוסף למסך הבית". הקובץ `.nojekyll` אומר ל-GitHub לא לעבד את האתר.

## איפה הנתונים

- הכל נשמר קודם ב-IndexedDB על האייפד עצמו (התקדמות, מילים שנוספו, ציורים, הגדרות), ומשם מסתנכרן לענן. הילד אף פעם לא מחכה לרשת.
- Safari לא מוחק נתונים של אפליקציה שנשמרה למסך הבית. ליתר ביטחון: **אזור ההורה → גיבוי** מוריד קובץ JSON, ואפשר לשחזר ממנו.
- נתונים של Safari רגיל ושל האפליקציה במסך הבית נפרדים (גם ההתחברות) — עובדים תמיד מאותו מקום.

## ענן והתחברות

**הפרויקט:** Supabase `ylpzytnvqmyjsxlzmfnl` (`https://ylpzytnvqmyjsxlzmfnl.supabase.co`). הסכמה ב-`supabase/schema.sql` (הרצה חוזרת בטוחה). ההגדרות הציבוריות ב-`js/config.js`: כתובת, מפתח publishable (ציבורי מעצם הגדרתו — מותר שיהיה בגיטהאב) ומייל המשפחה. מפתח ה-secret / service_role לא נכנס לקוד אף פעם.

**מה נשמר איפה**

| מה | באייפד (IndexedDB) | בענן |
|----|--------------------|------|
| הגדרות (שם, שלב, מהירות הקראה...) | `kv` | טבלה `settings` — שורה אחת, `data` כ-JSON |
| מילים שההורה הוסיף | `words` | טבלה `words` (מחיקה = `deleted = true`) |
| יומן קריאות (מה נשמע, תוצאה, ניסיונות) | `attempts` | טבלה `attempts` — רק הוספה, מזהה uuid מהמכשיר |
| סטטיסטיקה לכל מילה | `stats` | לא נשמרת — מחושבת מחדש מהיומן |
| ציורים | `drawings` (התמונה עצמה) | טבלה `drawings` + קובץ PNG ב-bucket פרטי `drawings`, בנתיב `<user_id>/<uuid>.png` |
| מונה הכוכבים עד הציור הבא | `kv` | לא נשמר (מקומי לכל מכשיר) |

כל כתיבה נכנסת קודם ל-IndexedDB ולתור (outbox), והתור עולה לענן ברקע: 2 שניות אחרי שינוי, כשהרשת חוזרת, כשהאפליקציה יוצאת לרקע, וכל דקה כשהיא פתוחה. באותן הזדמנויות האפליקציה גם מושכת שינויים מהענן — למשל מילה שנוספה מהטלפון מופיעה באייפד במילה הבאה. ציורים שנמצאים רק בענן יורדים לאזור ההורה רק כשמגיעים אליהם בגלריה, ואז נשמרים במכשיר.

באזור ההורה, מתחת לכותרת, שורת מצב: "מסונכרן לענן · לפני X", "מסנכרן...", "אין חיבור... (N ממתינים)", או שגיאה — וכפתור "סנכרן עכשיו".

**RLS:** בכל ארבע הטבלאות RLS מופעל, עם מדיניות אחת: משתמש מחובר רואה וכותב רק שורות שבהן `user_id = auth.uid()`. למשתמש אנונימי (`anon`) אין שום הרשאה על הטבלאות. ה-bucket `drawings` פרטי (לא ציבורי, רק PNG, עד 5MB), וכל משתמש ניגש רק לתיקייה ששמה ה-id שלו. לכן המפתח הציבורי לבדו לא חושף כלום — צריך גם את קוד המשפחה.

**כניסה עם קוד המשפחה**

- יש משתמש אחד ב-Supabase Auth: `parent@otiyot.app`. הסיסמה שלו היא קוד המשפחה (ספרות בלבד, לפחות 6, מומלץ 8 ומעלה). הרשמה ציבורית כבויה — אי אפשר ליצור משתמשים מהאפליקציה.
- בלי חיבור, כל האפליקציה היא מסך כניסה: מקלדת ספרות (אפשר גם מקלדת רגילה) וכפתור "כניסה" מ-6 ספרות. הקוד לא נשמר בשום מקום — רק החיבור (session) נשמר ב-localStorage (המפתח `otiyot-auth`) ומתחדש לבד, עד התנתקות.
- מכשיר שכבר התחבר נפתח מיד גם בלי רשת, והענן מתעדכן כשהרשת חוזרת.
- אם החיבור נגמר באמצע משחק (התנתקות ממכשיר אחר וכו') — הילד מסיים את המילה, ומסך הכניסה מופיע במעבר המסך הבא.

**שינוי הקוד:** אזור ההורה → הגדרות → חשבון → "שינוי קוד כניסה" (פעמיים את הקוד החדש). צריך רשת. המכשיר שבו שיניתם נשאר מחובר. Supabase מבטל בשינוי סיסמה את החיבורים של שאר המכשירים, ולכן הם יבקשו את הקוד החדש כשהחיבור שלהם מתחדש (בדרך כלל תוך שעה). באייפד של הילד מסך הכניסה יופיע במעבר המסך הבא — כדאי להכין את הקוד החדש.

**שכחתם את הקוד:** ב-Supabase → SQL Editor (במקום `NEW_CODE` — הקוד החדש, ספרות בלבד):

```sql
update auth.users set encrypted_password = extensions.crypt('NEW_CODE', extensions.gen_salt('bf'))
where email = 'parent@otiyot.app';
```

**התנתקות:** אזור ההורה → הגדרות → חשבון → "התנתקות" (לחיצה שנייה לאישור). לפני ההתנתקות האפליקציה מנסה להעלות את מה שממתין (עד 5 שניות). ההתנתקות היא רק מהמכשיר הזה — מכשירים אחרים נשארים מחוברים. הנתונים נשארים גם במכשיר וגם בענן.

**הפסקה בחבילה החינמית:** Supabase משהה פרויקט חינמי אחרי 7 ימים בלי שימוש. האפליקציה ממשיכה לעבוד באייפד כרגיל (הכל מקומי), אבל הסנכרון נכשל: שורת המצב באזור ההורה מראה שגיאת סנכרון או "אין חיבור" גם כשיש אינטרנט, והתור ממתין. כניסה במכשיר חדש תיכשל ("לא ניתן להתחבר כרגע" או "אין חיבור לאינטרנט"). מחזירים ב-Supabase Dashboard → הפרויקט → **Restore project** (כמה דקות), והתור שממתין עולה לבד אחרי זה. שימוש יומי באפליקציה מונע את ההשהיה.

**מחיקת כל הנתונים בענן:**

1. Supabase → SQL Editor:
   ```sql
   delete from public.attempts;
   delete from public.words;
   delete from public.drawings;
   delete from public.settings;
   ```
2. Supabase → Storage → `drawings` → לבחור את התיקייה של המשתמש → Delete (את הקבצים מוחקים מהממשק או דרך ה-API, לא ב-SQL).
3. מה שנשאר באייפד לא נמחק ולא עולה שוב לבד (רק שינויים חדשים עולים). כדי להתחיל מאפס גם במכשיר: אזור ההורה → הגדרות → איפוס התקדמות, או למחוק את האפליקציה ממסך הבית.

מחיקת המשתמש עצמו (Authentication → Users) מוחקת גם את כל השורות שלו בטבלאות (`on delete cascade`), אבל לא את קובצי הציורים ב-Storage (אותם מוחקים כמו בסעיף 2 למעלה) — ואז אין עם מה להיכנס עד שיוצרים משתמש חדש.

## סיכונים לבדוק באייפד

- **זיהוי דיבור עברי ב-Safari** דורש הכתבה מופעלת (הגדרות → כללי → מקלדת → הפעלת הכתבה) וחיבור לאינטרנט. אם אין — האפליקציה מציגה "אישור הורה" (קרא נכון / עוד לא) במקום.
- **זיהוי דיבור בתוך אפליקציה שנשמרה למסך הבית** (standalone) — היסטורית לא יציב בחלק מגרסאות iOS. אם לא עובד: לפתוח מ-Safari רגיל.
- **דיוק הזיהוי** עם דיבור של ילד בן 5 במילים קצרות (דָּג, יָם). רמת הסלחנות בהגדרות ההורה.
- הרשאת מיקרופון: בפעם הראשונה Safari שואל. אם נדחה — הגדרות Safari → מיקרופון לאתר.
